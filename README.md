# claude-code-harness

Обвязка для Claude Code: хуки и общая память, которые заставляют агента
вести контекст проекта между сессиями.

Это рабочий код из моей системы, которой я веду 14 проектов. Здесь слой
обвязки: пять хуков и минимальное хранилище, которого им достаточно.

## Зачем

У агентной разработки есть проблема, которая не лечится промптом: **агент
ничего не помнит между сессиями, а продукт живёт годами.**

Каждая новая сессия начинается с нуля. Агент заново читает кодовую базу,
заново выясняет, что уже сделано, и заново наступает на те же грабли.
Правило в `CLAUDE.md` он прочитает один раз в начале и к середине разговора
о нём забудет.

Инструкция в промпте выполняется с какой-то вероятностью. Хук выполняется
всегда. Поэтому дисциплина здесь вынесена из текста в код.

## Что делают хуки

### `SessionStart` — контекст вместо повторного чтения кода

При старте сессии агент получает из базы состояние проекта: на чём
остановились в прошлый раз, открытые задачи, блокеры, последние записи
других сессий.

Он не разбирает кодовую базу заново. Это экономит время и контекстное окно,
а длина контекста напрямую определяет стоимость каждого следующего запроса.

### `Stop` — нельзя закончить сессию молча

Главный хук. Логика намеренно грубая:

1. Читает стенограмму сессии. Правились файлы или было больше десяти вызовов
   консоли — значит работа была.
2. Смотрит в базу: появилась ли за эту сессию хоть одна запись в журнале или
   новая задача.
3. Работа была, записи нет — возвращает **код 2**. Claude Code показывает
   модели текст из stderr и не даёт завершить сессию, пока она не запишет
   сделанное.

Защита от петли: если среда уже перезапустила хук после блокировки
(`stop_hook_active`), проверка пропускается.

### `UserPromptSubmit` — задача не теряется посреди разговора

Срабатывает на каждой реплике человека. Если реплика похожа на постановку
новой задачи — добавляет в контекст короткое напоминание завести её до начала
работы, с уже подставленным слагом проекта по текущей папке.

Цена около 40 токенов и только на подходящих репликах. На «что это за фильм»
хук молчит.

### `PreToolUse` — секреты агенту недоступны

Перехватывает вызовы инструментов до исполнения. Блокирует попытки прочитать
хранилище секретов, ключ шифрования в связке ключей и команды работы с
секретами.

Принцип тот же, что я применяю в проде: **защита правами, а не формулировкой
в промпте.** Инструкцию можно переспорить другой инструкцией, перехватчик
переспорить нельзя.

### `SessionEnd` — закрытие записи о сессии

Проставляет время окончания. По этим записям потом считается, сколько
реально работали и по каким проектам.

## Что в репозитории

```
hooks/
  session.py     SessionStart и SessionEnd
  stop.py        блокировка завершения без записи
  prompt.py      напоминание завести задачу
  guard.py       перехват доступа к секретам
hub.py           минимальная CLI: проекты, задачи, журнал
schema.sql       четыре таблицы
settings.example.json   как это подключается
```

`hub.py` здесь — урезанная версия для справки. В моей системе CLI на 1353
строки покрывает ещё сделки, инфраструктуру, ссылки и секреты; тот код
завязан на мои данные и не публикуется.

Зависимостей нет. Только стандартная библиотека Python 3 и SQLite.

## Установка

```bash
git clone https://github.com/<user>/claude-code-harness.git ~/harness
cd ~/harness
python3 hub.py init
```

Дальше скопировать блок `hooks` из `settings.example.json` в
`~/.claude/settings.json`, поправив пути.

## Как пользоваться

```bash
python3 hub.py p add myproject "Мой проект" --path ~/code/myproject
python3 hub.py p show                      # состояние проекта
python3 hub.py t add "Починить выгрузку"   # задача
python3 hub.py t done 12
python3 hub.py log "что сделано, где проверить, какие грабли" -k result --actor claude
```

Агент пишет от своего имени через `--actor claude`, человек — от своего.
В журнале видно, кто что записал.

## Что писать в журнал

Запись должна быть такой, чтобы через месяц человек или другой агент понял
ситуацию без чтения кода:

- что теперь работает и где это проверить;
- где живёт прод и как выкатывается;
- принятые решения и почему выбран именно этот вариант;
- найденные грабли: что сломалось, из-за чего, как чинилось;
- чего не хватает: доступы, ключи, ответы клиента;
- на чём остановились и что логично делать следующим шагом.

Одна запись на смысловой блок работы. Секреты в журнал не пишутся никогда:
только факт «нужен ключ» и где он лежит.
